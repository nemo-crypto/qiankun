# 接入与部署指南

## 先理解应用边界

主应用负责导航、挂载容器与共享状态；子应用负责自己的视图与清理。子应用不直接 import 基座 store，而是接收 `getGlobalState`、`setGlobalState`、`onGlobalStateChange` 等能力。

`common/src/state.js` 的 bridge 为框架提供统一订阅接口。Vue 通过 Vuex 适配，React 通过 effect 订阅，原生应用直接订阅并更新 DOM。每次 mount 创建 bridge，每次 unmount 销毁；不要在模块顶层持有上次挂载的 props。

## 新增第四个子应用

1. 创建 workspace，声明应用自己的依赖，在根 package.json 的 workspaces 中加入目录。
2. 在 `config/settings.cjs` 加入唯一应用名、端口与入口文件。
3. 在 `main/src/micro-app.js` 注册 entry、基座激活路径与显示名称。
4. 入口导出 `bootstrap`、`mount`、`unmount`；独立模式主动 render。
5. 容器通过 `props.container.querySelector` 查找，卸载时销毁实例、计时器、事件和订阅。
6. 根据部署路径设置资源路径和 router base，再增加独立/嵌入/反复挂载测试。

统一 Webpack 配置以应用名生成 UMD 和 uniqueName，不需要修改已废弃的 Vue CLI / CRA 文件。

## 路由与资源是两条路径

| 场景 | 页面路由 | 资源入口 |
| --- | --- | --- |
| 开发基座 | `/sub-vue/about` | 子服务 `http://当前主机:7777/` |
| 开发独立 Vue | `http://当前主机:7777/about` | 同一子服务根路径 |
| 生产基座 | `/sub-vue/about` | `/subapp/sub-vue/` |
| 生产独立 Vue | `/subapp/sub-vue/about` | `/subapp/sub-vue/` |

`public-path.js` 接收 qiankun 注入路径，让懒加载 chunk 从正确入口请求；Vue Router 的 base 则决定页面地址。不要把 `/sub-vue` 当成生产静态资源目录。

## 生产文件摆放

将构建后的 `dist` 上传到如 `/srv/qiankun`：

```text
/srv/qiankun/main/index.html
/srv/qiankun/main/assets/...
/srv/qiankun/subapp/sub-vue/index.html
/srv/qiankun/subapp/sub-react/index.html
/srv/qiankun/subapp/sub-html/index.html
```

参考 `config/nginx.conf.example` 配置同源部署。`/subapp/` 必须先分发子应用资源；基座页面路径如 `/sub-vue/about` 回退到主应用 HTML；子应用独立深层路径回退到各自 HTML。资源缺失应返回 404，避免出现 Unexpected token '<'。

Nginx 文件是部署模板，本地测试验证的是 Node 预览服务器。实际发布前使用 `nginx -t` 验证目标机器配置，并补充域名、HTTPS 和访问控制。

## 验收清单

- 根目录全新 `npm ci` 后能启动，四个端口不冲突。
- 三个子应用独立可用；基座导航、浏览器回退、深层刷新正常。
- 用户和计数双向同步，多次往返不增加重复监听。
- 原生应用不会把用户输入作为 HTML 执行。
- 构建与预览通过，断网时显示错误，恢复后可以重新加载。

本示例没有身份认证、后端持久化或生产权限系统；共享状态中的用户名称是演示文本。
